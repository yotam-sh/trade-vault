TradeVault CLI Reference

Personal portfolio tracker for IBI brokerage — Israeli equities, Hebrew data

Python 3.10+ TinyDB Cross-platform

Overview

main.py is the command-line interface for TradeVault. It handles importing Excel exports from IBI brokerage, recording manual transactions, querying portfolio data, and maintaining the local TinyDB database.

The Flask web UI (server.py) runs separately on port 2501 and provides the full dashboard. The CLI is primarily used for importing data and one-off maintenance tasks.

Encoding note All data is in Hebrew. On Windows, the CLI forces UTF-8 output automatically. On Linux/macOS, ensure your terminal locale is UTF-8 (usually the default).

Quick start

# Install dependencies
$ pip install -r requirements.txt

# Start the web UI
$ python server.py

# Import today's daily portfolio snapshot
$ python main.py import daily "data/daily_data/apr_2026/data.xlsx"

# Import with a specific date
$ python main.py import daily "data/daily_data/apr_2026/data (1).xlsx" --date 2026-04-03

# Show portfolio summary
$ python main.py show portfolio
Linux / TrueNAS Replace python with python3 if needed. Inside a virtualenv or Docker container the python alias is typically correct.

import Import Excel data

Imports data from IBI brokerage Excel exports into the local database. Duplicate imports are detected via SHA-256 file hash and silently skipped.

Syntax

python main.py import <type> <file> [--date YYYY-MM-DD]

Type argument

TypeDescription
daily Daily portfolio snapshot (current holdings + prices). One file per trading day. Expects a single .xlsx file.
trades Trade history file from IBI. Accepts a single .xlsx or a folder path — folder mode imports all .xlsx files sorted by filename date (DDMMYYYY.xlsx).
morning-balance Folder of historic morning-balance exports (one file per day). Requires a folder path, not a single file. Computes daily P&L per holding using FIFO logic.

Options

OptionTypeDescription
--date optional Override the data date (YYYY-MM-DD). Defaults to today for daily imports; parsed from filename for trades and morning-balance imports.
--force flag Bypass the daily-import value-deviation guard, which otherwise rejects a file whose total deviates more than 50% from the previous snapshot (a wrong/partial file). The zero-rows guard is never bypassable.

Examples

# Daily snapshot — date defaults to today
$ python main.py import daily "data/daily_data/apr_2026/data.xlsx"

# Daily snapshot — explicit date (for a file imported late)
$ python main.py import daily "data/daily_data/apr_2026/data (1).xlsx" --date 2026-04-03

# Single trade file
$ python main.py import trades "data/trades/01042026.xlsx"

# Bulk trade import — all files in folder, ordered by filename date
$ python main.py import trades "data/trades/"

# Morning-balance folder (historic daily P&L reconstruction)
$ python main.py import morning-balance "data/morning_balance/feb_2026/"

add Add a transaction

Manually record a buy, sell, or cash deposit. Use this when a transaction is not present in the IBI export or for correcting the database.

Sub-commands

add buy

python main.py add buy <ticker> <shares> <price> [--date YYYY-MM-DD]
ArgumentTypeDescription
tickerrequired Yahoo Finance ticker (e.g. GNRS.TA). The holding must already exist in the database (imported via daily snapshot first).
sharesrequired Number of shares purchased (decimal allowed).
pricerequired Price per share in ILS.
--dateoptional Transaction date. Defaults to today.
Tax lot created automatically Every buy creates a FIFO tax lot. Subsequent sells will consume this lot in order.

add sell

python main.py add sell <ticker> <shares> <price> [--date YYYY-MM-DD]

Same arguments as add buy. Sells are processed FIFO across all open tax lots for the ticker. Realized P&L is printed to console.

add deposit

python main.py add deposit <amount> [--date YYYY-MM-DD]
ArgumentTypeDescription
amountrequired Deposit amount in ILS.
--dateoptional Transaction date. Defaults to today.

Examples

$ python main.py add buy GNRS.TA 100 52.30 --date 2026-03-15
$ python main.py add sell GNRS.TA 50 58.00
$ python main.py add deposit 50000 --date 2026-01-10

show Display portfolio data

Print portfolio data to the console. These are read-only queries.

Syntax

python main.py show <view> [--all]

Views

ViewDescription
portfolio Current portfolio value, cost basis, unrealized P&L, daily P&L, and per-position breakdown sorted by market value.
holdings List all active holdings (TASE symbol, name, ticker, security type). Use --all to include inactive/closed positions.
pnl P&L summary including unrealized, realized, and total return metrics.
trades Full trade history (buys/sells) plus a closed-positions summary with average buy/sell prices and realized P&L per position.

Options

OptionApplies toDescription
--all holdings Include inactive holdings (positions that have been fully sold).

Examples

$ python main.py show portfolio
$ python main.py show holdings
$ python main.py show holdings --all
$ python main.py show pnl
$ python main.py show trades

repair Repair data issues

Utility commands to fix data inconsistencies after re-imports or schema migrations.

Syntax

python main.py repair <target> [--from-date YYYY-MM-DD]

Targets

TargetDescription
morning-balance Recompute daily P&L for all morning-balance records. Removes stale non-trading-day entries (weekends and Israeli holidays with zero P&L) and recalculates each day's per-holding gain/loss accounting for quantity changes.
interpolated Clear all interpolated buy/sell transactions from a given date onwards and re-detect them by comparing consecutive daily snapshots. Use after bulk re-imports or if interpolated trades are incorrect.
lots Rebuild every tax lot from the transaction ledger (FIFO replay) and refresh snapshot cash/equity. Clears orphan/duplicate lots so open-lot shares match held positions — fixes the lot/position warnings reported by check.

Options

OptionApplies toDescription
--from-date interpolated Only reprocess from this date onwards (YYYY-MM-DD). Default: 2026-02-02.

Examples

$ python main.py repair morning-balance
$ python main.py repair interpolated
$ python main.py repair interpolated --from-date 2026-01-01
$ python main.py repair lots
Destructive operation repair interpolated deletes and re-creates interpolated transactions. Run python main.py db export first as a precaution.

set-ticker Assign a Yahoo Finance ticker

Assign a Yahoo Finance ticker symbol to a holding. The ticker is used by show portfolio and other commands that display per-position data.

Syntax

python main.py set-ticker <search> <ticker>

Arguments

ArgumentTypeDescription
searchrequired TASE paper number (numeric) or partial Hebrew name string. If multiple matches are found, all are listed and the command exits.
tickerrequired Yahoo Finance ticker to assign (e.g. TLV.TA, AAPL).

Examples

# By TASE paper number
$ python main.py set-ticker 1156926 GNRS.TA

# By partial name search
$ python main.py set-ticker "גרנות" GNRS.TA

set-yfinance Map TASE paper to Yahoo Finance

Creates a mapping between a TASE paper number and a Yahoo Finance symbol, then immediately fetches the English name and ticker from Yahoo Finance and stores it in the holding record.

Syntax

python main.py set-yfinance <tase_id> <yfinance_symbol>

Arguments

ArgumentTypeDescription
tase_idrequired TASE paper number (integer). Find it via show holdings.
yfinance_symbolrequired Yahoo Finance symbol. Israeli stocks usually end in .TA.

Examples

$ python main.py set-yfinance 1156926 GNRS.TA
$ python main.py set-yfinance 695437 NICE

refresh-yfinance Refresh Yahoo Finance data

Re-fetches stock info (English name, sector, description) from Yahoo Finance for all existing set-yfinance mappings. Useful after a library upgrade or when data is stale.

Syntax

python main.py refresh-yfinance

Example

$ python main.py refresh-yfinance

sync-holdings Sync active-flag with portfolio

Reads the latest portfolio snapshot and sets is_active = true for holdings with a current position (quantity > 0) and is_active = false for holdings no longer held. Useful after a bulk import or manual DB correction.

Syntax

python main.py sync-holdings

Example

$ python main.py sync-holdings

auth-setup Set up per-session login (TOTP)

Generates a TOTP secret + QR for the app's per-session login and saves it to a sidecar file on the db volume (db/auth.json) — never inside the database, so it is excluded from exports/backups. Login activates immediately (no restart). An explicit TOTP_SECRET env var, if set, takes precedence. The primary way to set this up is the web Maintenance page (Settings → Maintenance); this command is a CLI fallback.

Syntax

python main.py auth-setup

Example

$ python main.py auth-setup
# scan the QR, then add to .env:
#   TOTP_SECRET=JBSWY3DPEHPK3PXP...

check Reconcile database invariants

Verifies the derived data is internally consistent: each snapshot's positions sum to its market value, total_equity = market_value + cash, and open tax-lot shares match current positions. Prints any discrepancies and exits non-zero on hard errors (warnings, e.g. positions seeded without buy transactions, do not fail).

Syntax

python main.py check

Example

$ python main.py check
OK: all reconciliation checks passed.

db Database management

Export and import the TinyDB JSON database. Exports create a portable backup; imports replace the current database after running schema migrations.

db export

python main.py db export [output_path]
ArgumentTypeDescription
output_pathoptional Destination file path. Defaults to db_backup_YYYY-MM-DD.json in the project root.

db import

python main.py db import <input_path> --replace
ArgumentTypeDescription
input_pathrequired Path to the backup JSON file.
--replacerequired flag Safety flag — must be provided explicitly to confirm the destructive replace operation. The current DB is backed up automatically before replacing.

On import, several schema migrations run automatically: yfinance cache migration, field cleanup, dividend table removal, ticker_map removal, and import path normalisation.

Examples

# Export with default filename
$ python main.py db export

# Export to a specific path
$ python main.py db export backups/db_before_migration.json

# Replace DB from a backup (current DB is auto-backed-up first)
$ python main.py db import backups/db_before_migration.json --replace
Destructive operation db import --replace overwrites the live database. The previous DB is saved to db/*.bak automatically, but always verify the backup before proceeding.

check-libs Show outdated packages

Runs pip list --outdated to list packages with newer versions available, then updates the last-checked timestamp. The app also prints a reminder at startup if this check is more than 60 days old.

Syntax

python main.py check-libs

Example output

Checking for outdated packages...
Package    Version  Latest  Type
---------- -------- ------- -----
holidays   0.93     0.95    wheel
yfinance   0.2.50   0.2.54  wheel

Last-checked date updated to 2026-04-02.
Last-checked file The timestamp is stored in data/lib_check.json and is gitignored — each environment (dev, production) maintains its own schedule independently.

upgrade-libs Upgrade all packages

Runs pip install --upgrade -r requirements.txt using the same Python interpreter that is running the app (sys.executable), ensuring the correct virtualenv is always targeted on both Windows and Linux.

Syntax

python main.py upgrade-libs
Production note On TrueNAS/Portainer, run this inside the container (e.g. docker exec -it <container> python main.py upgrade-libs) to upgrade the container's environment, not the host. Rebuild the image to make upgrades permanent.

Data files

PathPurpose
data/daily_data/mon_YYYY/ Folder per month containing IBI daily snapshot Excel files (data.xlsx, data (1).xlsx, …).
data/IBI.xlsx Full transaction history export from IBI with right-side summary panel.
data/lib_check.json Stores the last library-check date. Not committed to git.
db/db.json TinyDB database (8 tables). Do not edit manually.
db/*.bak Automatic backup created before each db import.

Date format

All dates use ISO format: YYYY-MM-DD (e.g. 2026-04-02).

Trade and morning-balance filenames use DDMMYYYY.xlsx — the CLI parses the date automatically from the filename when no --date flag is given.

TASE trading schedule Before 2026-01-05 TASE traded Sun–Thu. From 2026-01-05 it switched to Mon–Fri. The app handles both regimes automatically. Israeli public holidays (Passover, Rosh Hashana, Yom Kippur, etc.) are also recognised as non-trading days via the holidays library.

Common workflows

Daily data import

# 1. Download today's export from IBI and save to the monthly folder
$ python main.py import daily "data/daily_data/apr_2026/data (5).xlsx" --date 2026-04-08

New holding setup (first time)

# 1. Import a daily snapshot (creates the holding record)
$ python main.py import daily "data/daily_data/apr_2026/data.xlsx"

# 2. Find the TASE ID
$ python main.py show holdings

# 3. Map to Yahoo Finance for English name + price data
$ python main.py set-yfinance 1156926 GNRS.TA

Moving DB to production (TrueNAS)

# On dev machine: export
$ python main.py db export db_transfer.json

# Copy db_transfer.json to the server, then inside the container:
$ docker exec -it tradevault python main.py db import db_transfer.json --replace

Checking and upgrading libraries

# See what's outdated
$ python main.py check-libs

# Upgrade everything
$ python main.py upgrade-libs

Web UI — Trade Log editing

The Trade Log page (/trades) now supports inline editing and deletion of buy/sell transactions directly from the browser. Every buy and sell row has an edit (✏) and delete (✕) button in its actions column.

Source badges

BadgeMeaning
AUTOTransaction was inferred from daily quantity deltas by the position tracker. May need correction if the daily summary was ambiguous.
EDITTransaction was manually edited via the web UI. The original inferred or imported price has been overridden.

Editing price per share

Click the ✏ button on any buy or sell row. Enter the corrected price in Agorot (the input is pre-filled with the current value × 100). The server recalculates total_amount, promotes source to 'manual' (so repair tools will not overwrite it), and sets an edited: true flag. For buy transactions the linked FIFO tax lot's cost_per_share is also updated.

Deleting a transaction

Click the ✕ button and confirm the dialog. The transaction is removed from the database. If the transaction was an interpolated buy (source='interpolated'), its linked tax lot is also removed. Use repair interpolated from the CLI afterward if you want to re-run trade inference from a clean state.

All buy/sell rows are editable — not just AUTO-badged ones. Trades imported from IBI trade files (source='trade_import') can also have their price corrected.

Web UI — Calendar Heatmap

The Calendar Heatmap (chart E on the Graphs page) visualises daily P&L across a selected period. Cells are colour-coded green (gain) or red (loss) relative to the maximum absolute value in the current view.

Period filter

Two dropdown buttons in the card header — Year and Month — let you select any combination of years and months. The filter is a true cross-product: selecting years [2025, 2026] and month [April] shows April 2025 and April 2026 only — not all months between them. The Clear item at the top of each dropdown resets that dimension back to the current year / current month.

View modes

ModeDescription
DaysCalendar grid — one column per week, one row per day of week. Non-selected days are transparent.
WeeksOne bar per ISO week; only weeks that contain a selected (year, month) date are shown.
MonthsOne bar per selected (year, month) pair in chronological order.

Separators (Days mode)

SituationSeparator
Single month selected — between week columnsThin line (1 px, low opacity)
Multiple months, adjacent (e.g. Mar → Apr same year)Medium line (2 px)
Multiple months, non-adjacent (e.g. Apr 2025 → Apr 2026)Thick line (3 px, high opacity)

Navigation

Hover over the grid to see a tooltip with the exact date and P&L value. The entire row (day of week) is highlighted as you move across the grid, helping you track the same weekday across multiple weeks or months. The hovered cell itself gets a 2 px accent-colour outline for precise identification.
